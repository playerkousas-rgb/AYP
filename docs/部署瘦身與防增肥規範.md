#  部署瘦身與防增肥規範（Vercel）

> 目的：防止 Vercel 儲存空間配額爆滿，同時**功能／UI／體驗 100% 零倒退**。
> 原則：人會忘記，機器不會 —— 所有規範都落在自動守門（`scripts/lint.js`、`scripts/check.js`、`scripts/build.js`），`npm run build` 失敗即擋下增肥。改規範＝改這三個檔＋在本文件落紀錄。

## 1. 部署管線（只上傳最終產物）

| 設定 | 值 | 作用 |
|---|---|---|
| `vercel.json → buildCommand` | `npm run build` | 先 lint＋check 再產 `dist/`，增肥直接擋在部署前 |
| `vercel.json → outputDirectory` | `dist` | **只上傳部署產物**，開發環境／測試／文件一律不進 CDN |
| `vercel.json → installCommand` | `npm install --omit=dev --no-audit --no-fund` | 生產建置**不裝 devDependencies**（jsdom 等只供本機測試） |
| `.vercelignore` | 見檔 | 上傳黑名單：`.git`、`node_modules`、`tests/`、`docs/`、`*.md`、備份檔、`uploads/` 等 |

- `dist/` 由 `scripts/build.js` 產生：**核心 5 檔＋assets/**，逐檔 sha256 校驗、禁止多餘檔案。
- 執行時依賴（`dependencies`）**永遠為零**——本站係純靜態 PWA，唔准加運行套件。

## 2. 圖片規範（AVIF／PNG 分工）

- 所有圖片放 `assets/`。守門預算：**單一 ≤ 120KB、assets 總和 ≤ 200KB**（`check.js` 強制）。
- **圖示由向量原稿＋腳本產生，唔好手改 `assets/` 入面嘅圖**：`design/icon.svg`（512，全出血、maskable 安全）＋`design/favicon.svg`（32，細尺寸簡化版）→ `node scripts/make-icons.js`。
  腳本要一次性 `npm i --no-save --package-lock=false @napi-rs/image`（刻意唔入 `package.json`，保持零依賴、Vercel 建置不變肥）。產出可重現（再跑 sha256 不變），並自動守門：maskable 安全圈（半徑 0.40）、logo PNG 不透明、AVIF 解碼回讀 PSNR。`design/` 由 `.vercelignore` 擋，唔進部署。
- **格式分工**（平台限制由 `check.js` §11 強制）：

  | 用途 | 檔案 | 格式 | 點解 |
  |---|---|---|---|
  | 分頁 favicon | `favicon-32.avif`＋`favicon-32.png` | **AVIF 主＋PNG 回退**，兩個都 32×32、AVIF 宣告喺前 | Firefox 有測試報告（caniuse #6880）支援 AVIF favicon；Chromium 解碼器已實測，但 headless 冇 favicon 驅動、Safari 冇可靠資料，所以留 0.5KB PNG 回退 |
  | header 標誌 | `logo-192.avif`＋`logo-192.png` | **AVIF＋PNG 回退**（`<picture>`） | 頁內圖，AVIF 優先係標準做法 |
  | manifest 192／512（any＋maskable） | `logo-192.png`、`logo-512.png` | **PNG，唔可以 AVIF** | Chromium `manifest_icon_selector.cc` 嘅 `kLimitedMimeTypes` 只收 PNG／SVG／WebP；AVIF 圖示會被當作冇圖示 |
  | iOS 主畫面 | `rel="apple-touch-icon"` → `logo-192.png` | **PNG，不透明** | iOS 主畫面圖示只有 PNG 可靠，透明會被填黑；192 縮落 180 唔失真，所以唔另存 180 檔 |

  ```html
  <link rel="icon" type="image/avif" sizes="32x32" href="assets/favicon-32.avif">
  <link rel="icon" type="image/png" sizes="32x32" href="assets/favicon-32.png">
  <picture><source srcset="assets/x.avif" type="image/avif"><img src="assets/x.png" alt="…"></picture>
  ```
- **favicon 排法有原因**（Chromium `favicon_handler.cc`／`select_favicon_frames.cc`）：候選圖按宣告 `sizes` 同 16／32px 嘅相似度計分並穩定排序（單一尺寸以 **32×32 最高分**，48×48 反而輸）；`FaviconURL` 冇 MIME 欄位，即 `type` 唔參與揀選。逐個下載，**只有「下一個候選嘅宣告分」嚴格高過「目前最佳實測分」先繼續下載**（`ShouldDownloadNextCandidate`）；未有有效圖（例如 AVIF 解碼失敗）就一定會落去下一個。所以：兩個都 32×32、AVIF 排前 → Chrome 桌面 AVIF 成功就**只下載 AVIF**，失敗先自動回退 PNG。`sizes="192x192"` 嗰個 `rel=icon` 桌面分數最低、唔會被下載，但係原有設計，留畀要大圖嘅場景。
- **Google 搜尋結果 favicon 只支援 BMP／GIF／ICO／PNG／JPEG／PPM／TIFF（唔包 AVIF／WebP／SVG），並建議 >48px**（Search Central〈Define a favicon to show in search results〉）：所以 PNG 回退同 192 PNG 唔可以刪，唔好改成 AVIF-only。
- **揀格式前先量度**（2026-10-02，同一套平面向量圖、畫質相當）：

  | 尺寸 | PNG-8（量化＋oxipng） | AVIF（ravif） | 結論 |
  |---|---|---|---|
  | 512 | 6.5 KB | 3.1–4.1 KB | AVIF 較細，但 manifest 唔收 → 用 PNG |
  | 192 | 2.0 KB | 1.6 KB | AVIF 細約 21% → header 用 AVIF 主 |
  | 32 | **0.5 KB** | 1.0 KB | **PNG-8 反而細一半**：AVIF 容器開銷實測 0.28KB（不透明）／0.44KB（帶 alpha，favicon 即係咁），連淨編碼資料（0.6KB）都已大過成個 PNG-8 |

  AVIF 勝在相片／漸層／大圖；平面向量細圖標，調色盤 PNG-8 已同 AVIF 同級甚至更細。**舊版嘅肥主因係帶雜訊／漸層嘅點陣圖，唔係格式**；今次由 105.5KB 瘦到 11.6KB，靠嘅係「平面向量重畫＋調色盤量化＋面積平均縮圖（冇振鈴）」。日後如只求最細，favicon 可改純 PNG（再慳約 1KB：刪 AVIF 一行＋一個檔，連同 `sw.js`、`check.js` 引用）。
- **新增任何資產＝三連動**：① 在 `index.html`／`manifest.webmanifest` 引用；② 加入 `sw.js` 的 `ASSETS` 並**遞增 `CACHE` 版本號**（否則舊用戶食舊快取）；③ `check.js` 會雙向核對「被引用必存在／存在必被引用／sw 清單＝根檔案＋全部 assets」，漏任何一步 build 即紅。
- 高解析**點陣**母檔（如 1024px PNG）**唔入倉**；git history 係你嘅備份。向量原稿（`design/*.svg`，數 KB）入倉。

## 3. 防增肥預算（`scripts/check.js` 強制）

| 項目 | 上限 | 現值（2026-10-02） |
|---|---|---|
| 部署總和 | 400 KB | ≈ 193 KB |
| assets 總和 | 200 KB | ≈ 11.6 KB |
| 單一資產 | 120 KB | 最大 6.5 KB（logo-512.png） |

- 要調預算＝**刻意**改 `check.js` 常數＋更新本表＋落 changelog，唔准順手改。（2026-10-02 圖示瘦身後現值遠低於上限，上限刻意未動；想重新收緊「棘輪」就照呢條規矩改。）
- 禁入倉：`*.bak *.tmp *.old *.orig *.log *~`、`.DS_Store`、`uploads/`、`coverage/`（`.gitignore`＋`check.js` 雙保險）。
- `assets/` 入面**無人引用嘅檔＝死重**，check 直接失敗——杜絕「放低張圖忘記刪」。
- 未使用嘅 i18n 頂層鍵只出**警告**（現存：`langLabel`、`NEW_SYSTEM_NOTE`，屬內容儲備，刻意保留）。

## 4. 快取與更新（PWA）

- `vercel.json` headers：`/sw.js` 與 `/`、`/index.html` 用 `no-cache`／`must-revalidate`（保證更新即生效）；`/assets/*` 7 天＋`must-revalidate`；全站加 `nosniff`／`X-Frame-Options`／`Permissions-Policy`。
- `sw.js` 只快取 `res.ok` 嘅同源回應；離線回落永遠回有效 `Response`。
- `sw.js` 預快取用 `cache: "reload"` 繞過 HTTP 快取：`/assets/*` 有 7 日 `max-age`，唔繞過嘅話，同名資產原地換圖時新 SW 會預快取到舊圖，而 fetch 係 cache-first，舊圖會一直食到下次升版。

## 5. 出 RELEASE 前清單

1. `npm run lint && npm run check && npm run build && npm test`（102 項 DOM 回歸）。
2. 改過資產（包括原地換圖）→ 遞增 `sw.js` 的 `CACHE` 版本。改圖示＝改 `design/*.svg` 後跑 `node scripts/make-icons.js`，唔好手改 `assets/`。
3. `npm run preview` 本機睇一次 `dist/`。
4. 有瀏覽器環境先跑 Playwright（見 README；本沙盒 CDN 封鎖可跳過，以 jsdom 為準）。
